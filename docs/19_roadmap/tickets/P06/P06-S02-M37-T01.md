**Goal:** Stream live workflow updates without a page reload (FR-096, ADR-0014).
**Input:** A subscription.
**Output:** Live events over /api/v1/stream.

Real `/api/v1/stream` route reusing the existing `InProcessEventBus`
directly (no parallel mechanism). Design fork resolved via
`AskUserQuestion`: no Topic/Channel Manager exists, so topics map onto
`Event`'s own real fields (`workflow:{id}`->`workflow_id`,
`system`/`approvals`->`event_type` prefix); `experiment:{id}` refused,
`Event` has no `experiment_id` field. Real auth (token verify + RBAC),
9 real tests including a published `Event` genuinely reaching a
subscribed client. Disclosed: no real Kernel component publishes to
the bus in production yet — this wires the real consumer side only.
