**Goal:** Make each variant's runs genuinely use that variant's model.
**Input:** A variant's model_alias; the run's workflow definition.
**Output:** Runs pinned to the variant model (overview.md §5 step 5).

Without this every variant ran on each agent's own configured model, so
the comparison compared identical conditions. Investigation resolved one
mechanism: every real agent reads its model from `inputs['modelAlias']`,
forwarded by the step executor from `step.model_alias` (`PromptedAgent`
and every SE-pack agent's `_REQUIRED_INVOCATION_FIELDS`); the config
layer-6 and Router seams do not intercept it. So `pin_definition_to_model`
overrides every agent step's `model_alias` (recursing into parallel
branches) on a run-time copy — the catalog definition is never mutated
(ADR-0022). Proven: a recording executor confirms variant A's runs
executed against model A, B's against B. Keyless completion against a live
provider remains inherent, unchanged.
