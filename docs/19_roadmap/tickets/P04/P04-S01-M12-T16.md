**Goal:** Remove the schema blocker under `GET /gates/trends` ("pass/fail over time").
**Input:** `evaluation.gate_results`, which had no timestamp column at all.
**Output:** A server-defaulted, indexed `created_at` that SQL can bucket.

Product-owner decision, 2026-08-13, from three real options. Joining
`workflow_instances` needs no migration but yields `NULL` for exactly the
runs a blocking gate halted. Decoding the ULID already inside `result_id`
(trusted today for keyset ordering) gives the true time but cannot be
grouped in SQL at all. So: a column, exactly as `0035` added one to
`llm_calls` for the identical gap.
Server-defaulted, never caller-supplied — no writer should be able to
backdate a trend point. Existing rows get `now()`, the honest choice
`0035` documents, not a fabricated history. **The route is not built
here**: the blocker is removed, the work is not. Proven by a real
`date_trunc` aggregation.
