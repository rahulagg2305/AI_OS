**Goal:** A real config source for git-push (remote URL, author identity, protected branches).
**Input:** `AIOS_GIT_*` environment variables.
**Output:** A real `GitIntegrationService`, or the existing safe no-op.

No ticket named this; recommended by the prior Task, investigated, proceeded. `AIOS_GIT_*` env vars over Configuration Manager: the
codebase's own `configuration_manager/models.py` already states deployment-specific/credential-adjacent values never become
`PlatformConfig` fields (`AIOS_DATABASE_URL`/`OTEL_EXPORTER_OTLP_ENDPOINT` precedent). `build_git_integration_service_from_env` returns
`None` when unconfigured, raises `GitIntegrationConfigError` if a remote is set but author identity/`protected_branches` is missing or
empty (closes R-001's own named "empty protected_branches is not safe" finding). `GitPushAgentEntrypoint.remote_url` reads
`AIOS_GIT_REMOTE_URL` via plain `os.environ` (never a Kernel import — pack stays at zero forbidden-import violations), mirroring
`build_default_sandbox_executor`'s bare-env-default shape. `SqlAgentRegistry` gained an optional `git_service` param, threaded through
`_bind_pack_context_if_receiver`/`build_pack_context`; `bootstrap.py`'s real `se.delivery_pipeline` composition now builds and passes
one. Proven: real env vars populate a real, behaviorally-verified `GitIntegrationService` (author identity in real `git commit` args,
configured branch genuinely refused); absent env still resolves to `None`. Zero regression: full Docker/Postgres-gated suite green.
