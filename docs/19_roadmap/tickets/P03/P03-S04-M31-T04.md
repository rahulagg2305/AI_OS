**Goal:** Make the real Git Integration Service reachable via ToolInvoker.
**Input:** An agent's `context.tools.invoke(tool_id, inputs)` call.
**Output:** A real Git operation, or a real, typed failure.

No ticket named this; investigated, no fork found, proceeded (same precedent T01/sandboxed_tool.py already set: a platform tool lives in
`kernel/`, module_path stays a board label). Followed the established `platform.sandbox.run_command` shim pattern, not the zero-arg
registry-resolved path — that path's `PackContext` has no DB-engine access, and `GitIntegrationService` genuinely needs one (audit log).
Three new platform tool ids (`platform.git.commit`/`create_branch`/`push`) declared in the SDK; real dispatch added to
`ToolInvokerAdapter`, an optional `git_service` param (unchanged behavior when absent, same shape as `registry`). No credential support
in this tool's own schema — `ToolInvoker.invoke` carries no SecurityContext to resolve one with, a disclosed, deferred gap, not
fabricated. Proven: a real `adapter.invoke()` call reaches the real service, the real sandbox, and a real `git` subprocess —
commit/branch/push verified by reading the real repo/remote back independently, and a protected-branch push refused with the remote
untouched.
