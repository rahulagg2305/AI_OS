**Goal:** Make "protected-branch integration requires human approval" real, not structural.
**Input:** `se.delivery_pipeline`'s own final steps.
**Output:** A real pause before push, resumed only on an authorized decision.

No ticket named this. Investigated first: a real PR-creation/merge mechanism (new GitHub API integration) is not the smallest real design — direct push to
a protected branch is already permanently, structurally impossible (`GitIntegrationService.push` §5.1), so there is nothing to gate there. The real,
buildable gap is R-001's own broader one: `se.delivery_pipeline` ran fully autonomously with zero human oversight before its one real, external action.
Fix: a real `human_approval` step, `approve-git-push`, between `documentation` and `git-push` in the shared `delivery_pipeline.yaml` (bumped 1.7.0),
reusing the existing Human Approval Manager unchanged — no parallel mechanism. Since this is the shared, canonical definition every real caller
(production route + tests) drives, every run now genuinely pauses there — a real, deliberate behavior change: 7 existing tests reaching that point were
updated from asserting `COMPLETED` to the new, correct `WAITING_FOR_HUMAN` (their own real assertions all read steps that already ran before the gate).
Added `resume_pipeline_after_approval` (`delivery_pipeline.py`, sharing `_build_pipeline_composition` with `build_pipeline_trigger`) since the existing
`trigger()` closure is one-shot with no way to re-enter a paused instance. Proven in one real run: git-push (and its real remote) receives nothing while
pending; an unauthorized decision is refused, remote still untouched; only a real, RBAC-authorized decision resumes to a genuine commit and push. HTTP
route to submit a decision remains real, disclosed, deferred (matches human_approval.py's own existing scope). Zero regression: full suite green.
