**Goal:** Close the "manual-JWT-crafting gap" — grant/revoke a real approver:<class> role.
**Input:** An admin principal naming a target principal, role, and reason.
**Output:** A real, persisted, audited grant/revoke, genuinely enforced on the next decide().

No ready ticket; investigated `token_verifier.py` and found `Principal.roles`
comes solely from the JWT claim — no DB-backed role lookup exists anywhere.
Built `security.role_grants` (new schema/migration) + `RoleAdministrationService`
(admin-gated, reusing `ADMIN_ROLE`, audited via `governance.audit_log`,
mirroring `AccessBroker`). Grants *augment*, never replace, token roles:
`ApprovalService.decide()` optionally unions active grants into
`principal.roles` before the unchanged class-scoped check runs. Proven via
real Postgres, one continuous flow: refused (no grant) -> admin grants ->
identical unchanged token now succeeds -> admin revokes -> fresh decision
refused again; exactly one granted/revoked audit row each. Service-layer
only, no HTTP route (mirrors T04/T05's own precedent).
