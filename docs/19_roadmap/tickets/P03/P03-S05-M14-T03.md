**Goal:** A tool cannot exercise a permission its agent or workflow lacks (FR-018).
**Input:** The principal-workflow-agent-tool chain.
**Output:** Enforced narrowing at each hop.

**Real, tested computation; enforcement still awaits its data source.**
`narrow_permissions`/`is_permitted` implement ADR-0023's exact intersection
(principal ∩ workflow ∩ agent ∩ tool), proven against the real security
property (a broad principal genuinely narrowed by restrictive declarations;
no hop can ever grant a permission the principal lacks). Not yet wired into
a real invocation: no code anywhere parses a workflow's/agent's/tool's
declared `permissions` out of a manifest into a runtime value — that is
Capability Manager territory, not this ticket's `module_path`. See
`ai_os_kernel.security_manager.narrowing`'s own docstring.
