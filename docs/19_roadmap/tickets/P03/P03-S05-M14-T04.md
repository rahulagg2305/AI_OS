**Goal:** Pause at an approval point; resume only on an authorized decision (FR-013).
**Input:** A human_approval step.
**Output:** waiting_for_human; never approves on timeout.

Not on the ready list (T05 undone); investigated and built both together —
closes R-001's permanent hard rule. `HumanApprovalStepExecutor` creates a
pending approval, raises `HumanApprovalPendingError` (caught specially by
`advance()`, not a failure) to reach `waiting_for_human` via new
`mark_waiting_for_human`; reuses the existing lease-acquire guard so nothing
re-polls a waiting instance. Fixed a real bug found along the way: a second
`run_to_completion` call against an already-waiting instance misreported
`FAILED`; added genuine `WorkflowRunOutcome.WAITING_FOR_HUMAN`. Step id must
match a `humanApprovalPoints` entry (new cross-validator). Proven via real
Postgres: genuine repeated pause, resume only via `decide()`, timeout never
approves, anonymous/double decisions refused, reject halts before next step.
