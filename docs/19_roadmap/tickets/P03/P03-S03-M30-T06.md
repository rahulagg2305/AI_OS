**Goal:** A real HTTP route for a human to decide a paused instance, and genuine resumption.
**Input:** A pending approval on a real, paused `se.delivery_pipeline` run.
**Output:** A real decision, then a genuine resume through to completion.

Investigated first: the existing worker loop does NOT compose with se.delivery_pipeline — its `_lifespan` composition has no quality_gate/decision/
human_approval executor and uses the demo's own agent_registry, not the credential/git_service-threaded one. A real, previously-latent race: once
decide() flips an instance to running, that already-polling loop could rediscover and mis-advance it (silently no-op the approval, then fail
git-push against the wrong registry) before a correct resume ran. Stopped and presented three real options; product owner chose: decide route
resumes synchronously (`resume_pipeline_after_approval`, sharing `_build_pipeline_composition` with `build_pipeline_trigger`) and the generic loop
excludes se.delivery_pipeline entirely (`list_runnable_instances`' new `exclude_definition_ids`). Real course-correction found via a real request: a
first `require_permission(APPROVAL_DECIDE)` gate was genuinely broken — a principal holding only the realistic `approver:approve-git-push` role was
refused before ApprovalService's own correct, class-scoped check ever ran. Fixed by exporting bare `authenticate` and deferring authorization to
ApprovalService entirely, reverting the new flat permission. Proven end to end: real Postgres, a real paused instance (Echo-driven setup, no live
LLM needed), a real TestClient HTTP decide call, unauthorized refused (remote untouched), authorized genuinely resumes to a real commit and push
(`AIOS_SANDBOX_BACKEND=local`, since the real registry's own Docker default can't reach a host-local remote). Zero regression: full suite green.
