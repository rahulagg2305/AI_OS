**Goal:** Move a proven-but-idle step type into genuine pipeline use.
**Input:** decision/parallel plus the real delivery_pipeline composition.
**Output:** A real, meaningful decision step genuinely running.

Product-owner-directed (not a prior ready-list Task). Chose `decision` over
`parallel`: parallelizing lint+test would need each branch's output
independently persisted and re-plumbed through `_GATE_SOURCES`/`_STEP_SOURCES`
— real, proven behavior the zero-regression constraint declines to disturb.
New `route-after-build` reads `build`'s own real `written` field (captured,
never acted on): routes to `lint` unchanged when true, straight to `test`
(skipping a wasted Lint invocation+gate) when false. `documentation`'s
`["build","test"]` requirement stays satisfied either way, since `test`
always runs. Proven via two real Postgres runs: true branch unchanged; false
branch skips lint (no step record), fails at `test` on a real missing file.
