**Goal:** §5's Access / Filter Layer.
**Input:** A knowledge query from a real principal.
**Output:** Only the items that principal may see.
Verified 2026-08-13: `knowledge_manager.md` states there is **no Access /
Filter Layer** and that §2's "permission-aware retrieval" is "entirely
absent". `QueryEngine` returns every match to any caller.
This matters beyond tidiness: `KnowledgeResolver` is already wired into
a real running workflow (`se.delivery_pipeline`'s
`requirements-analyst` step), so knowledge genuinely reaches an LLM
prompt today with no authorization step anywhere in the path.
**Expect a design fork:** no knowledge permission exists in ADR-0023 or
`permissions.py`, and `knowledge.documents` carries `trust` but no
owner/classification column. Both the permission vocabulary and where
the filter binds (query vs resolver) are undecided. Stop and ask.
