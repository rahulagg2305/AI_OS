**Goal:** Separate evaluating a result from enforcing blocking vs warning severity.
**Input:** A gate result.
**Output:** A policy decision.

Evaluation (pass/fail) was already separate in practice; enforcement
was not — any resolved severity != "blocking" raised
UnsupportedGateSeverityError outright. Now: "blocking" fail still
raises (unchanged); "warning" fail returns normally with a real
severity flag, never blocking. Removed the now-dead error class.
gate_result_recorder.py's own hardcoded severity="blocking" column
fixed to read the real value, avoiding mislabeling a genuine warning
result. Both real pack gates stay "blocking" — zero prod behavior
change; proven for "warning" via real, schema-conformant fixtures.
