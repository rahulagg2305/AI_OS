**Goal:** Let the system discover registered WorkflowDefinitions system-wide.
**Input:** WorkflowDefinitionCatalog's write-only registrations.
**Output:** A real reader + the worker loop genuinely running in `_lifespan`.

Product-owner-directed (not a prior ready-list Task). Investigation found the
write-only catalog genuinely blocks only 2 of the 4 named capabilities
(sub_workflow, worker loop — both need arbitrary cross-definition lookup);
decision/parallel need none (self-contained within one definition; blocked
only by "not declared in any real pipeline yet," unrelated). Added a single,
exact-key `get(definition_id, version)` reader — lossless round-trip of what
`register` already writes; no listing/update/versioning. `WorkflowWorkerLoop`
now resolves definitions via this reader, not a composition-injected mapping.
Wired `run_worker_loop` into `_lifespan` (4th background task, mirroring the
lease reaper) — proof: it discovers/completes a real instance with no manual
call, proven live (real Postgres, TestClient): "proven, unused" to "running."
