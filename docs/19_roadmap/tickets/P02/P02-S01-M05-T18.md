**Goal:** Close the two Workflow Engine gaps `T17` disclosed rather than absorbed.
**Input:** A terminal `failed` transition; a definition's `failureHandling`.
**Output:** A real `workflow.failed` domain event; a validated `onError`.

`mark_failed` wrote only the engine's own `state.transitioned` row,
which nothing subscribes to — so `NotificationService`'s `workflow.failed`
category had a subscriber and no producer. It now writes the outbox event
in the *same* transaction, mirroring `workflow.completed` exactly.
`failureHandling.onError` was required of every definition and read by
nothing: declaring `escalate` silently got `halt`. Product owner,
2026-08-13: close the vocabulary to `halt` (the only implemented
behaviour) and **reject** `escalate` rather than invent semantics no
document defines. `bootstrap.py`'s demo declared `on_error`, a misspelled
key the old "must not be empty" check never caught; 28 fixtures normalised.
3 Postgres tests (all fail when reverted), 3 loader tests.
