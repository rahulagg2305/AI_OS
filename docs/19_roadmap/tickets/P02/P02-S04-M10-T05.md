**Goal:** Make `knowledge.memory_items.provenance` mean something.
**Input:** A memory write.
**Output:** Provenance the platform computed, not the caller asserted.
The column was write-through, so a caller could assert anything —
decorative. `MemoryWrite` now has **no `provenance` field at all**
(`extra=forbid`, so an attempt is a loud error); the service composes it.
**The record states its own trustworthiness rather than implying it.**
Verified: `workflowId` (a real FK — Postgres refuses a fake one).
Computed, caller cannot influence: `recordedAt`, `recordedBy`,
`schemaVersion`, and `trust` — a constant `untrusted` (ADR-0016 control
1, matching what `MemoryResolver` already asserts; a parameter would let
a caller misrepresent provenance, per `DERIVED_CONTENT_TRUST`).
Declared and documented as the weakest field: `stepId`/`agentId`, which
nothing cross-checks until a real `SecurityContext` reaches this site.
5 unit tests + a real-Postgres `jsonb` round trip. 18 unit + 5 integration.
