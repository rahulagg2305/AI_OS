**Goal:** Stop the R-015 timing flake failing real CI (third occurrence).
**Input:** The single-tick concurrency test's tight 0.2s-step / 0.4s (2x) bound.
**Output:** A wide, jitter-resistant bound expressed relative to serialized time.

R-015's own entry set the bar: investigate on a third real-CI occurrence — this
push was it (`assert 0.456 < 0.4`, after 2026-08-10 run 31390101661 at
`0.448 < 0.4`). Root cause: fixed per-instance DB/scheduler overhead (~0.25s)
exceeded the 0.2s step it measured, leaving the 0.4s bound only ~0.14s of
headroom — a busy Ubuntu runner could miss it with no regression in the code
under test. Fix: step 0.2s->0.5s, assert `elapsed < step * instances * 0.7`
(1.05s) against a 1.5s serialized time, so the signal dominates the overhead.
No production code changed; the tick's real concurrency guarantee is unchanged,
only the proof's margin. Proven: 5 consecutive AIOS_ENV=ci local runs pass.
