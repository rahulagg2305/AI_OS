**Goal:** Make `evaluation.gate_results.duration_ms` a real measurement.
**Input:** A gate execution.
**Output:** The genuine wall-clock duration of that gate.
`duration_ms` was derived from `completed_at - started_at`, and both real
write paths stamp those columns in one statement — **structurally always
`0`**. The gate now times itself (`perf_counter`) and publishes
`durationMs` in its outputs.
**The failure path was first landed broken; now genuinely fixed.**
`QualityGateFailedError` gained `duration_ms`, but `advance` built its
error payload as `{type, message}` only — written, never read — so a
*blocking* gate still persisted `0`, the exact bug this closes. Its
integration test passed only by hand-building an error dict production
never produced. `_step_error_detail` (`service.py`) now carries it.
End to end: `se.delivery_pipeline` records **6ms**; its own stale
`assert duration_ms == 0` genuinely failed. 32 unit + 148 integration.
