**Goal:** Give module 10 real code of its own.
**Input:** The already-real `SqlMemoryStore`.
**Output:** A real `memory_manager` package that owns the memory concern.
Verified 2026-08-13: `kernel/src/ai_os_kernel/memory_manager/` is **one
18-line docstring-only `__init__.py` with zero classes**. The real store
lives at `persistence/memory_writer.py`, and `MemoryResolver`
(module 8) calls it directly. That is why this module reads 18% — the
package genuinely does not exist yet.
`memory_manager.md` §6 names `MemoryService.write()` as the **only
mediated write path**; nothing implements it, in the Kernel or the SDK.
This ticket builds that service here, over the unchanged store.
**Expect a design fork:** `platform_sdk.md` §5.5 specifies
`MemoryService` as an SDK Protocol, but the SDK ships no such Protocol
and `SqlKnowledgeWriter` has the identical unresolved relationship.
Kernel-local vs SDK Protocol is undecided — stop and ask.
