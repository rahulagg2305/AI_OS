### Stage B/C – Documentation Reconciliation, Fixture Fix, and Real DockerSandbox Verification (Health-Audit Follow-Up — Not a New Increment)

- **Read `implementation_status.md`, `DOCUMENTATION_INDEX.md`, `agents.md`, `workflows.md`, and every doc the health audit named before changing any of them.** This step's own approved framing was explicit that it is a reconciliation step, not development — no new features, and "zero behaviour change" for every rename, proven rather than assumed.
- **Agent/workflow naming fork resolved.** `architect` → `architecture`, `test` → `qa-test`, renamed in `manifest.yaml`, `pack.py`, `delivery_pipeline.yaml` (`agents[]` and every step's own `agentId` — **not** the workflow-local `steps[].id`, a deliberately different, unrenamed namespace), and every pack-level/Kernel-level test's own agent-id constant. `documentation` already matched `agents.md`'s own catalog exactly — confirmed, not changed. `build` had no genuine fit among the other 14 documented ids; `agents.md`'s own Agent Catalog gained a new, honestly-scoped entry for it instead of a force-fit or a silent, undocumented id. `se.delivery_pipeline` was checked directly against `workflows.md` §4's own `se.implement_task` and found to genuinely diverge in shape, purpose, and participating agents — kept as its own id, given its own real section in `workflows.md` rather than forced into that shape. Both docs gained a "Currently Implemented Subset" section naming exactly which agents/workflows are real today (4 of 16; 1 of 7) so a fresh reader is never misled. **Verified zero behaviour change twice**: the full existing test suite (616 tests) passes with only id-literal changes, and the manual end-to-end pipeline trace was re-run with the new ids, producing byte-for-byte identical output to the pre-rename run.
- **Every doc-drift gap the audit named is now closed**: `context_manager.md` §4 and `workflow_architecture.md`'s Context Management section record `WorkflowStepOutputResolver`; `capability_pack_contract.md` carries a dated, explicit exception note for the real, live direct-Kernel-import compromise; `manifest_schema.md` (new validation rule 11, renumbering the rest) and `platform_sdk/schemas/manifest.schema.json` itself (a real, tested `if`/`then`: `modelAlias` required only when `permissions` contains `llm:invoke`) were both fixed — the QA/Test Agent's manifest entry no longer carries the now-unnecessary decoy value; `llm_gateway.md` §15's dead `platform_sdk/contracts/llm.py` reference now points at the real files; ADR-0016 gained an additive "Implementation naming note" (not a rewrite — this codebase's ADR process has no in-place-amend path for an Accepted decision) cross-referenced from `security_architecture.md` §5.1, recording `SandboxRuntime`/`SandboxExecutor` as the same seam under two names.
- **New shared test helper, `tests/integration/_postgres_fixture.py`** (`postgres_container()`), replacing the identical, independently-repeated `PostgresContainer(...)` construction line across all ~30 of this tree's own `database_url` fixtures — the one real, current, thirty-times-repeated case ADR-0004 itself says justifies a shared helper. A genuinely unreachable daemon now raises a clean `pytest.skip()` with a clear reason. **Verified both directions directly**: `DOCKER_HOST` forced to a nonexistent pipe produced a clean, fast (~2 second), clearly-reasoned skip (16/16, no raw exception); the real suite then ran successfully with Docker genuinely available (below).
- **Docker Desktop became available partway through this step — the first time in this project's history — and the resulting real run found and fixed two genuine bugs in `DockerSandbox`.** (1) `containers.create()` does not implicitly pull a missing image the way `docker run` does — fixed by pulling explicitly and retrying once on `ImageNotFound`. (2) A real Windows/npipe-specific bug: every stdin-delivery attempt hung until the wall-clock timeout, traced by direct, live debugging to `NpipeSocket.shutdown()` being implemented as a full `close()` rather than a half-close, combined with this backend's own `detach=True` leaving the container's `StdinOnce` config field unset — the daemon had no configured signal to treat the closed attach socket as stdin EOF. Fixed by using `detach=False` (verified: previously-hanging `cat` now exits the instant its stdin closes), which has no other effect on this class's own control flow. A regression-locking assertion (`kwargs["detach"] is False`) was added to the existing mocked unit test.
- **With both fixed, all 7 real, unmocked `DockerSandbox` live guarantee tests pass against a genuine daemon** — network isolation, filesystem containment (both directions), non-root identity, timeout-kill, guaranteed removal, and real stdin delivery, none of which had ever been confirmed against a real daemon before this step. **A full real run of the entire integration suite reports 218 passed, 10 skipped (correctly, no live API key), 0 failed** — the single largest verification-debt closure in this project's history, executed in one sitting rather than accumulated further. Every container this session's own runs created was confirmed cleanly removed afterward.
- **Still deliberately a reconciliation/verification step, not new development**: no new agent, workflow, or Kernel capability was built; the only non-documentation code changes are the id renames, the schema conditional fix, the shared Postgres fixture helper, and the two real `DockerSandbox` bug fixes the newly-available daemon surfaced. `DockerSandbox` is still not wired in as any agent's own default — the `sys.executable`-portability gap recorded in the previous step's own §5 is unchanged and remains the prerequisite.
- `mypy --strict` (277 source files) clean, `ruff check`/`ruff format --check` clean. Unit suite: **616 passed**, zero regressions. **Integration suite, genuinely executed: 218 passed, 10 skipped, 0 failed.** One unrelated, pre-existing, timing-sensitive flake (`test_multi_provider_routing.py`) under full-suite load, passed cleanly in isolation — not caused by this step.
