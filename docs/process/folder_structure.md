## The single most important fact about this repository's structure

**Git does not track empty directories.** Every "planned" folder below has **zero tracked files**, which means it **does not exist at all in a fresh clone** — it is not an empty directory a reader will find and wonder about; it is simply absent. The only placeholder directories that survive a clone are `workspace/scratch/` and `workspace/temp/`, which are held open by real `.gitkeep` files.

Verified 2026-07-28 by `git ls-files <dir> | wc -l` for every directory named in `PROJECT_INDEX.md`. The repository has **458 tracked files** in total.

Practical consequence: if you are working in a fresh clone and a document references `platform_services/` or `dashboard/` or `ai_context/`, **do not create it speculatively and do not treat its absence as a mistake.** The directory arrives with the step that puts real content in it.

## What this means practically

- If a task references a folder, **check the table above** — it is per-row and dated, and it is the part of this document to trust. **Corrected 2026-08-11 (full-project audit): two bullets that used to sit here flatly contradicted that table and are removed.** They claimed the Dashboard, the Voice/Jarvis pack, Project Intelligence and the CLI "have no real code," and that `platform_sdk/` was "nearly empty." All four of those first claims were false by then, and the SDK one was false too — measured at the time of correction: `dashboard/src` 22 tracked files / ~4,062 lines; `tools/aios` 26 files / ~1,459 lines; `capability_packs/project_intelligence` 18 files / ~2,530 lines (plus a real `manifest.yaml`); `platform_sdk/src` 26 files / ~3,554 lines across 25 real modules. The Voice/Jarvis claim was misleading rather than simply stale: there is genuinely **no** `capability_packs/voice_jarvis/` distribution (see the `capability_packs/` row for why it was rejected), but the real Platform Integration Layer does exist at `kernel/src/ai_os_kernel/voice_jarvis/`.
- The still-true general warning those bullets were reaching for: **a folder existing does not mean the subsystem is reachable.** Several packages have real, tested code that no production composition constructs — `caching`, `document_processing`, `speech_gateway`, `storage_service` (and `memory_manager/`, which is a docstring-only `__init__.py` whose real store lives at `persistence/memory_writer.py`). For "is it wired?", use `../19_roadmap/feature_inventory.md` (the module authority) and risk register **R-018**, not directory listings.
- `platform_sdk/`'s own sub-layout is uneven and that is deliberate, not incomplete: `contracts/`, `models/`, `errors/` and `testing/` carry real content, while `sdk/` and `utilities/` are tracked but intentionally hold only a docstring `__init__.py` (`utilities/__init__.py` states this itself: "Deliberately empty beyond this docstring in v1.0.0", because no real pack needs those helpers yet).
- **One directory was removed during the 2026-07-28 consolidation audit**: `capability_packs/software_engineering/` (underscore) — a dead, never-tracked duplicate of the real hyphenated `capability_packs/software-engineering/`, referenced by nothing. This follows the `capability_packs/analytics/` precedent (investigated, confirmed dead, removed, recorded). See `../19_roadmap/history/025_documentation_consolidation_audit.md`.
- This table goes stale as real work lands. Update it in the same step that puts real content into a Planned row — alongside `PROJECT_INDEX.md`'s Status column and `../19_roadmap/feature_inventory.md`.
